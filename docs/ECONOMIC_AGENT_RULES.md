**Purpose:** improve EcoSim as an auditable policy-comparison simulator while preserving its agents' basic roles, meaningful individual differences and practical simulation speed. Comparisons include progressive taxation, healthcare financing/access, inflation mechanisms and eventually explicit ownership/governance arrangements. A plausible mechanism and an honestly measured result matter more than a favorable outcome for any policy.

**Authority and baseline:** Ayman's instructions take precedence. This document governs the proposal cycle; the [working contract](ECONOMIC_AGENT_WORKING_CONTRACT.md) supplies implementation details and the [proposal template](ECONOMIC_AGENT_PROPOSAL_TEMPLATE.md) supplies the required output. Source determines what the engine currently does. This review used the working tree, including W01–W05, over commit `4f693890b5f133c2c6c1dcbec9b1ec91ced97b46`, verified equal to live `origin/main`. The commit alone does not identify uncommitted changes: use the [source hashes and symbol index](reviews/evidence/ECONOMIC_AGENT_RULES_SOURCE.json). Before a later assignment, the orchestrator checks for source drift and supplies one common snapshot to all writers.

There are three distinct kinds of statement below:

- **Binding rule:** writers must follow it. A proposed exception is explicit and remains outside the selected implementation until the orchestrator resolves it and versions the common contract.
- **Current behavior:** source-backed description of this baseline. Describe it accurately; do not silently replace it with a textbook model.
- **Known limitation:** an abstraction, defect or unverified capability. It may be investigated or improved; documenting it does not make it a permanent requirement.

## 1. Binding rules

| ID | Rule every writer follows |
|---|---|
| R01 — Scope | Write a bounded proposal, with at most three prioritized changes. No simulation edits during the proposal stage. A reviewer assigned an individual case proposes a general mechanism or counterexample, never a special advantage for that ID. |
| R02 — Preserve roles | Extend the existing household, firm and institutional roles. Preserve progressive taxation; redesigning brackets is not a main task. Do not replace an agent wholesale, add an ideological success bonus, or optimize aggregate outcomes by directly overwriting GDP, employment or welfare. |
| R03 — One shared economy | Use the current tick order, market resolvers and settlement owners. A role assignment does not grant ownership of shared orchestration. Declare any requested timing, market, schema or counterparty change before another proposal depends on it. |
| R04 — Accounting | Name the payer, recipient, instrument, amount, units and recognition phase for every changed flow. Each due payment has one settlement owner; partial installments must not be duplicated. Deposits, borrowing, principal repayment, interest, taxes and dividends have different meanings. An opening endowment, external source, money creation or write-off must be identified explicitly. |
| R05 — Scarcity | Respect resolved inventory, labor, housing units, medical capacity, liquidity and financing constraints. A change in payer does not create real supply. State what happens when resources run out: rationing, waiting, refusal, default or a specifically funded support rule. |
| R06 — Decisions and information | Separate intended actions, allocated outcomes and settled balances. Name the information visible at the decision phase, including expectations and announcements. No access to future realized outcomes or another actor's private state without an explicit information assumption. Do not infer that a method is side-effect-free from a `plan` or `should` name; inspect its writes. |
| R07 — Individuality | Use shared behavior code with stable identities and persistent, bounded traits plus changing resources, skills, health, beliefs and experience. Identify actual readers of each proposed trait. Differences must be capable of changing a decision; equal actions under binding constraints are allowed. Do not require a separate algorithm or language-model call for every individual. |
| R08 — Policy transmission | Trace the immediate flow, first changed decision, affected counterparties, next decisions, delays and feedback. Include a competing/adverse effect and a case where the chain stops. Mark each link as existing, proposed or hypothetical. No automatic claim that a benefit spreads to everyone. |
| R09 — Comparable experiments | Hold initialization, execution mode, metric definitions, observation times and capabilities common except for the declared intervention. Specify how revenue and financing adjust. Preserve pre-policy subgroup membership when estimating subgroup effects, and separately report entry, exit and transitions. A common seed alone does not prove a valid paired counterfactual. |
| R10 — Evidence | Label executed result, source finding, economic hypothesis and chosen simplification separately. Cite the owning source symbol and a relevant primary economic source for a new real-world mechanism. A citation supports the mechanism it studies, not an arbitrary parameter or a whole regime comparison. Declare uncertainty and unsupported claims. |
| R11 — Computation | Keep new decision work bounded and compatible with batch execution. No default per-actor network calls, full population-by-firm scans or unbounded histories. Estimate both time and memory; measure the integrated package under the performance rules in section 6. |
| R12 — Integration | Identify field writers/readers, counterparties, scalar/batch paths, caches, configuration, metrics and serialization consumers. Preserve established names/defaults unless the selected change explicitly revises them. The orchestrator resolves shared assumptions before implementation and verifies composed behavior afterward. |

R04–R05 are requirements for a proposed change and its affected boundaries, not a claim that all existing paths already reconcile. They do not impose constant total money under every possible monetary institution, or prohibit technological improvement. Any new creation process needs its own explicit accounting and resource model. The existing L01–L12 laws in the [working contract](ECONOMIC_AGENT_WORKING_CONTRACT.md#2-shared-laws-accounting-resources-and-execution) continue to apply.

## 2. The economy writers are starting from

| Actor/system | Current role and interactions | Boundary to preserve or explicitly revise |
|---|---|---|
| Household | One decision unit combines individual attributes and ordinary employment with a household budget. Receives wages, possible owner/CEO income and transfers; purchases goods/services, rents housing, seeks care, deposits and borrows. | One ordinary employer link must agree with the firm's roster. Ownership/CEO income is a separate relationship. This is not yet a full family/demographic model. |
| Firm | Employs workers, forms demand expectations, plans output/prices/wages, produces, sells, invests and may distribute surplus. Firms differ within personality classes. | Workers, owners, customers, lenders and government are counterparties. Investment and pricing mechanisms already exist; inspect them before adding another response to the same signal. |
| Government | Sets bounded policy levers, taxes, transfers and several support/investment programs. Receives fiscal revenue and bears treasury-funded disbursements. | Progressive wage taxation stays. Current financing is asymmetric; negative treasury cash does not establish a complete sovereign-debt market. |
| Bank | The optional bank holds household deposits, funds loans subject to its reserve rules, services loans and records defaults. The main large-economy factory creates one. | Deposits are bank liabilities and household assets. Bank-funded and treasury-funded loans have different funders; `govt_backed` currently means treasury-funded, not a contingent guarantee. |
| Housing/healthcare providers | Special firm categories also use dedicated rental, mortgage, care, queue and workforce routines. | They cannot be modeled correctly by changing ordinary goods demand alone. Physical capacity and specialized settlement remain explicit. |
| Economy/server | `Economy` coordinates plans, allocation, settlement and statistics. The server applies validated runtime policy updates at safe boundaries. | Economic actors do not independently advance time or mutate all counterparties. A proposal writer is a development reviewer, not an actor inside a running economy. |

The large-economy factory seeds Food, Housing, Services and Healthcare baseline providers and queues private firms. Its initial private-firm allocation excludes Housing and Healthcare; that is a factory choice, not a universal prohibition on later entrants. Opening cash and productive assets are initial conditions, not earnings. Baseline providers also receive household owners in this factory: `is_baseline` is a special operating regime, **not proof of treasury ownership**. Ownership draws use module-level Python randomness; reproducibility depends on the calling runner/session initializing or restoring that state, not `CONFIG.random_seed` alone. Initial age, skill and cash partly follow ID patterns; these are synthetic distributions, not a calibrated population. Sources: [S1], [S2], [S3].

## 3. Shared clock and execution order

One engine tick represents approximately one week; `TimeConfig` defaults to 52 ticks per year and 10 warmup ticks. Some conversions also hard-code 52, so changing that config field alone does not establish a consistent new timescale. New fields must declare stock versus flow, per-tick versus annual rates, model currency versus physical quantity, and nominal versus price-adjusted values. No currency or country calibration is implied. [S4]

The table records the major operations in their actual call order inside `Economy.step`, retaining its phase labels. The function body is the complete specification. Some operations are conditional on warmup, stabilizers, bank availability or execution mode. **Writers use this order unless proposing an explicit shared timing change.** [S1]

Do not demand that every intermediate cash snapshot already reflects both sides, or rerun a stateful planner merely to log its inputs. ## 4. Market and financial rules

**M01 — Goods and prices.** `_clear_goods_market` processes household plans in their existing order. A firm-specific request addresses that firm; a legacy good-name request uses suppliers sharing that exact `good_name`, ordered by price and ID. Category choice occurs earlier in household awareness/purchase planning, which emits firm-ID targets; clearing does not itself pool all goods in a category. Quantity is capped by remaining supply. This is sequential allocation, not an auction or simultaneous equilibrium solver. Food inventories and flow services have different supply rules. Services can use an effective price floor based on costs/debt, which can update the posted price during clearing. Preserve these distinctions when reasoning about price response. [S1], [S2]

The resolver records allocations and seller revenue without rechecking/debiting current household cash at that point. Earlier planning, deposit withdrawal and later household settlement handle affordability through different paths. A proposed correction must trace all of them; do not describe current clearing as an atomic, fully cash-reconciled transaction. A fairer rationing rule, new search process or simultaneous market is a shared market change, not a harmless sorting refactor.

**M02 — Labor.** Vacancies, skills, reservation wages and recruitment/matching rules constrain hiring. Matched employment determines production; ordinary wages involve firm costs and later household receipts. Doctor/resident assignments have specialized restrictions. Changing a wage rule must account for vacancies, affordability, actual wages, household expectations and government floors, not just the displayed offer. Sources: `Economy._run_labor_matching`, roster synchronization, `HouseholdAgent.plan_labor_supply`, `FirmAgent.plan_wage`. [S1], [S2]

**M03 — Healthcare.** Requests depend on health/scheduling rules; there is no direct price input in the current request rule. Provider queues, worker visit capacity, payment support and medical lending constrain delivery. Queue prioritization specifically favors sick doctors; do not assume a general urgency-based triage system. Care changes health, which can change future requests even without a direct demand-price channel. “Free at point of use” must specify payer, coverage, provider revenue, budget exhaustion and waiting; it never means unlimited capacity. [S1], [S2]

An active positive sector subsidy targeting healthcare supplies the requested public share; otherwise the request uses `healthcare_visit_subsidy_share`, whose default is zero. Thus no direct public visit subsidy is requested under those default conditions, while deposits/medical loans can still finance patient payments. Actual public payment is limited by treasury cash and the shared per-tick subsidy cap. If the patient cannot pay after withdrawal/credit attempts, the visit is refused and the patient leaves the queue, with later re-request possible; do not count that as continued waiting. When no priority doctor leads, the scan origin rotates by tick/provider ID, so the queue is not simply first-in-first-out. [S1], [S4]

**M04 — Housing.** Reconcile household/provider rental records and occupancy with units. Rent, repairs, construction and mortgages have specialized paths. The current housing abstraction is not a full land, property-transaction or construction-input market. An ownership or rent-control proposal must name which of those institutions it actually changes. [S1], [S2]

**M05 — Deposits and loans.** Use actual withdrawals and recorded deposit liabilities. Current deposits respond to both household tendencies and the bank's deposit rate. Preserve the W01–W02 actual-funder repayment routing and single servicing path for registered medical loans. Partial repayments reduce the appropriate obligation; interest and principal are identified separately. A default/write-off is not another cash payment. [S1], [S2], [S6]

The bank currently lends from available reserves under its reserve constraint; do not silently substitute endogenous deposit-money creation. Ordinary `BankAgent.originate_loan` computes a level installment with `payment_loans.v2_payment` at `annual_rate / ticks_per_year` per tick over `term_ticks`; the contractual total is `payment_per_tick * term_ticks`, and `interest_income_per_tick` is `(total - principal) / term_ticks`, which `collect_repayment` uses to split each payment. Borrower-side mirrors read the loan record rather than recomputing interest. Before v1.3 the total was principal multiplied by `1 + annual_rate` regardless of term, so a 520-tick loan owed one year of interest over ten years; loans originated before the change keep their stored schedule. The legacy and payment arms now agree on the installment and the on-schedule total but still differ on interest timing (the payment arm accrues on the declining balance, legacy books the total at origination and splits proportionally), write-off size, and early or partial payment. Legacy housing-expansion mortgages are bank-ledger records (`subtype = "housing_mortgage"`) whose installment is `v2_payment` at annual rate over 52 ticks, equal to `_compute_housing_pmt`; their `LoanContract` services them, capped at the record's remaining balance, and an exiting firm's mortgage is written off with its other loans. The legacy treasury direct loans (the `_issue_firm_loan` fallback and the no-bank entrant seed), the government bailout emergency loans in `_execute_bailouts` (both arms; `emergency_loan_term_years` × `ticks_per_year` ticks at `emergency_loan_interest`), the no-bank household medical loan (52-tick term) and the affordability estimates in `FirmAgent` (`_estimate_working_capital_payment`, the service-infrastructure gate) use `v2_payment` too. Exactly two sites still use the one-year formula (principal × (1 + annual rate), whatever the term), both direct treasury claims on the payment arm under that arm's own accepted contract: the treasury branch of `_issue_firm_loan` (`amount * (1.0 + rate)`) and the entrant treasury seed in `_maybe_create_new_firms` (`requested * 1.01`); a proposal that depends on them must say so. On legacy, a firm's `bank_loan_payment_per_tick` holds every bank loan's installment, including mortgages and service-infrastructure loans, from origination until the loan is paid off, and firm debt service reads it once plus `loan_payment_per_tick` for treasury loans; the payment arm rebuilds the same mirror from its registered claims. A firm's treasury direct loans have no per-loan record: they are pooled in `government_loan_remaining` and `loan_payment_per_tick`, and on legacy the installment mirror returns to zero when the pooled balance is paid off; the payment arm's direct-claim collector does not yet clear it. Any further rate-convention change remains an explicit financial-contract change with migration and comparison consequences. [S2]

**M06 — Government.** New policy actions use the canonical policy schema/bounds and the existing validated application path. Preserve progressive wage taxation, and distinguish the headline rate, bracket rules, assessed liability and actual revenue. Profit-tax pricing responses already exist. State whether extra revenue funds transfers, services, investment, debt reduction or another declared use; a tax comparison needs that closure. Treasury balances can currently become negative through transfers while investments and sector/visit subsidy disbursements have cash limits. Do not clamp all actors' cash to zero, invent a creditor for an existing overdraft, or count an overdraft twice in a signed financial balance. [S1], [S2], [S5]

Current wage bands use percentiles of the tick's positive wages: unemployed households with no wage are excluded from the cut-points (and owe no wage tax). The default fixed-seed band multipliers rise with the band, and every profit-tax bracket is capped at 0.60. The headline rate and band multiplier determine a rate applied to the whole wage, rather than marginal slices; relative thresholds and rate notches are therefore part of this baseline. Phase 10 debits the planned wage tax without a cash-based collection limit, and phase 11 recognizes the same aggregate: there is no separate wage-tax nonpayment mechanism. Band scalers are not currently canonical policy levers. Disclose these facts when comparing tax settings; they do not make bracket redesign a priority. [S1], [S2], [S5]

**M07 — Ownership and regimes.** Workers, owners, managers, public-service obligations and funders are distinct roles. A label such as capitalism, socialism or communism is insufficient: specify ownership, control, investment allocation, prices/access, surplus distribution, loss-bearing and transition rules. Keep outcome definitions and real constraints common where the intervention does not explicitly change them. Do not infer institutional ownership from a baseline flag. [S3], [S7]

|---|---|---|

Do not call all profit taxation inert or claim property settlement is wholly missing. A snapshot fix still needs an executed path check. [S1], [S2] |
| K02 | Legacy firm-entry seed cash (bootstrapped entrants' 5,000-30,000, and entrants whose bank or treasury seed fell through) and the legacy demand shock (household cash added or removed with no counterparty) are intentional external flows (owner decision 2026-09-29); the economy records them, signed, in `external_injection_this_tick` and `external_injection_total`, and the drift tool reports drift both raw and net of them. Endowment, exit (for example, an exiting firm's negative cash balance disappears with it) and some fallback finance paths still have unresolved counterparties; public-finance closure is incomplete. | Name the exact affected flow and financing assumption; treat a recorded external flow as outside money, not as a leak. The completed loan fixes do not certify economy-wide conservation. [S6], [S7] |
| K03 | The live legacy batch path uses this week's settled take-home wages (after wage tax, including CEO pay) and actual transfers, with liquidity/drawdown constraints. Some sampled traits have no core reader. | The v1.5 timing slice adds an explicit net-receipt spending response on legacy. | K04 | Inflation target is stored without a working inflation-control channel; some other exposed switches/fields are also inactive. Stabilizer toggles can change private decision rules as well as public support. | Map actual readers and capabilities. Do not interpret an inactive control as an intervention, or a stabilizer comparison as government size alone. [S6], [S7] |
| K05 | Current GDP is a nominal sales proxy; price measures are not a household expenditure-weighted CPI; household cash inequality is not comprehensive net-worth inequality; poverty and unemployment conventions have comparison limits. | Name formulas, populations and observation time. Do not silently improve a measure in only one comparison arm. [S1], [S7] |
| K06 | Investment/productivity and miscellaneous-revenue routing are aggregate shortcuts; there is no complete production network, monetary system, trade sector or demographic lifecycle. | Add only the missing mechanism necessary for the stated policy question. A whole new economy is not a prerequisite to a useful bounded correction. [S1], [S2], [S7] |
| K07 | Seeds, hashes, manifests and selected snapshots exist; complete checkpoint branching and matched external disturbances have not been established. Factory ownership depends on caller-managed global RNG state; miscellaneous-revenue tax draws include the payment amount in their key. | Audit RNG/state coverage, initialization and policy-dependent paths. Do not assume the same config seed gives the same owners or disturbances. Record replay is not proof of a general counterfactual capability. [S1], [S3], [S6], [S7] |
| K08 | Synthetic traits and repeatable runs are not external calibration or empirical validation. | Results describe this model under stated assumptions. National forecasts or real-world causal magnitudes need additional evidence. [S7], [S8] |

These are starting cautions, not an exhaustive defect register or permission to fix everything. Preserve the [readiness queue](ECONOMIC_WORK_READINESS.md): W01–W05 are complete; later mechanisms remain at their recorded readiness until a bounded slice is specified and selected.

**K06 detail that affects spending comparisons:** `_collect_misc_revenue` sends a random 0–20% tax to the treasury and the remainder to a pool. The pool is distributed equally across a randomly selected beneficiary group that grows to at most 50 households; inflows after the phase-6.7 distribution remain for a later distribution. Separately, `_recycle_capital_investment` credits calculated firm capital expenditure equally to all households. These distribution rules can change household resources and inequality independently of productivity benefits. Public-spending, education, construction and R&D proposals must name their affected routes; they are not neutral accounting placeholders. [S1]

## 6. Computer and simulation constraints

The default remains a synchronous engine with shared code and compact per-actor state. Development reviewers can work independently outside the run. They do not become thousands of live language-model actors. The existing government LLM integration is an optional controller at a validated boundary; household narration and single-firm experiments do not establish population-wide live control. [S5], [S8]

- **Bounded cost:** favor reused market arrays, indexes, small consideration sets and batch paths. New per-tick searches must declare how cost scales with households, firms, loans and queues. New histories require retention limits; optional detailed traces stay outside the default hot path. Do not describe work as free because it is vectorized.
- **One cumulative budget:** adopt a default engineering target of at most **5% added median and p95 engine tick time for the selected integrated package**, against a matched baseline. This is a project working threshold chosen to operationalize Ayman's speed constraint, not a measured guarantee or a number he supplied. It is not 5% per worker. Report memory change and bound new state; no numeric memory ceiling has yet been established.
- **Measure the actual workload:** use repeated matched runs at representative 1,000- and 10,000-household sizes, including a developed private economy. Hold hardware/runtime, mode and configuration fixed. Separate a changed number of active firms from added per-actor algorithm cost. Account for measurement variability; a revised budget or workload needs a documented reason before interpretation. Existing package evidence is in [the performance report](reviews/ECONOMIC_CONCRETE_PERFORMANCE.md).
- **Handle inconclusive timing honestly:** the earlier normal-mode 1,000-household baseline repeat medians varied by about 6.5%, already larger than the 5% target. A point estimate below 5% is not proof of compliance. For future acceptance, predeclare the repetition/uncertainty method, use interleaved matched baseline/candidate runs, and report each relevant population/mode cell as within budget, over budget or inconclusive. If the uncertainty range straddles 5%, repeat or simplify rather than declaring a pass. Do not silently drop the smaller population or choose a favorable cell; the historical measurements remain point estimates with their recorded limits.
- **Cadence is economic behavior:** normal mode plans consumption and updates wellbeing each tick. Legacy performance mode refreshes seller choices every five ticks, monetary budgets every tick and wellbeing every ten; a newly funded empty basket gets seller choices immediately, and a scaled cached basket keeps the planner's food ceiling and one-unit housing cap. Named payment scenarios keep the previous complete-plan cache (five ticks) and wellbeing every ten. Wage percentile caches refresh every five ticks and continuing-worker wage updates occur every fifty in the current path. Hold mode and cadence fixed across arms; reducing refresh frequency requires a behavior check, not just a faster benchmark. [S1]
- **Reproducibility:** preserve stable IDs and pre-policy traits; declare random sources and keys. Logging must not consume decision randomness. A local proposal must not reseed global RNGs or add order-dependent draws without an explicit integration plan.
- **Finite valid state:** new state needs type, units, bounds and exhaustion behavior. Reject NaN/infinite values and physically invalid allocations. Do not hide economic distress with arbitrary balance resets. Some current unsubsidized household purchases can also leave cash negative after earlier payments; signed-balance caveats are not treasury-only. Trace the affected path rather than asserting universal nonnegative cash or silently clamping it.

A proposal may recommend a more expensive optional module when the policy question warrants it. It must expose its cost and capability differences; it cannot silently change the default cost budget or compare unlike execution modes as if they were equivalent.

## 7. Assignment boundaries and change control

| Writer | Primary proposal scope | Counterparties/interfaces it must inspect |
|---|---|---|
| Household | Work, spending/saving, needs, expectations, persistent differences | Scalar/batch consumption, actual wages, tax/transfer timing, credit/deposits, rent, care and owner income |
| Firm | Production, expectations, pricing, hiring/wages, investment and survival | Customers, workers, owners, suppliers/abstract inputs, creditors, fiscal support and entry/exit |
| Government | Tax/transfer rules, financing closure, service obligations and policy application | Tax snapshots, household/firm settlement, treasury/bank claims, provider capacity and policy schema |
| Bank | Deposits, lending, interest, liquidity, repayment and default | Every borrower/depositor, actual funder, government finance, housing and medical contracts |
| Healthcare | Requests, access/payment, queueing, delivery and workforce | Patient health/liquidity, medical credit, provider receipts, government budgets and training/capacity |
| Housing | Occupancy/rent, maintenance, capacity and financing | Tenant liquidity, rental records, owner/provider cash, mortgages, construction and property taxes |
| Sampled individual case | Inspect one household/firm's available information and constraints; propose a general mechanism or counterexample | The same counterparties as the corresponding role; explain which other agents the mechanism would cover, without privileged treatment for the sampled ID |
| Orchestrator | Source verification, shared rules, conflicts and the integrated plan | All roles, including actors without an assigned writer; shared phase order, metrics, configuration, serialization and cumulative cost |

Read dependencies are broader than write ownership. Most roles share `agents.py` and `economy.py`; eventual implementation uses exact symbol assignments and isolated patches/worktrees, not simultaneous edits to the same working-tree file. Do not introduce new coordination infrastructure simply to produce documents.

Every proposal includes the rules version, source snapshot, applicable R/M/K IDs, field read/write map, downstream-effects chain, acceptance cases and cost estimate. Use the [proposal template](ECONOMIC_AGENT_PROPOSAL_TEMPLATE.md). Compliance cannot be certified by ticking a box: cite the affected decision and settlement paths.

A requested common-rule revision states: **rule ID → current behavior → proposed behavior → policy reason/evidence → affected roles/phases/fields → accounting and resource consequences → comparison/compatibility consequences → cost → verification → migration or rollback**. Label it a request until resolved. Writers can complete independent analysis while a dependency is unresolved, but cannot present the dependent design as settled.

The orchestrator first audits each document against source, then compares proposals for accounting, timing, behavioral, institutional, measurement and performance conflicts. It can resolve routine in-scope choices; it escalates a material new modeling preference to Ayman when the existing instructions do not settle it. Publish a versioned common resolution before dependent implementation. Do not silently amend another author's preserved proposal. “Accept as specified” means ready for selection, not implemented or empirically validated.
