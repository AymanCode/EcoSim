# Audit of the frontend learning redesign spec

**Assessment:** The screen direction is implementable, but section 6 understates the backend work and section 3 does not yet define a reliable experiment lifecycle. The most consequential gaps are experiment-wide cap enforcement, initial policy setup, live event coverage, frame size, and the AI decision card’s evidence claims. I reviewed the current working tree without changing files; local `HEAD` matches the local `origin/main` ref, while many files under audit are uncommitted.

## A. Claims that are wrong or unverifiable

- **“Three of the roughly 150 metrics the backend computes each tick reach the browser”** and **“discrete events exist only in the warehouse”** ([spec:10](docs/superpowers/specs/2026-09-24-frontend-learning-redesign-design.md#L10)). The current frame has dozens of metric fields, histories, tracked subjects and firms, policy changes, and the latest LLM decision; the checked-in fixture has 40 `metrics` keys ([backend/server.py:2612](backend/server.py#L2612), [frontend-react/src/test/fixtures/frame.json:1](frontend-react/src/test/fixtures/frame.json#L1)). Labor, healthcare, and regime events also exist in the economy’s per-tick memory before warehouse conversion ([backend/economy.py:270](backend/economy.py#L270), [backend/server.py:1733](backend/server.py#L1733)). **Design impact:** frame exposure and event coverage are real problems, but the premise exaggerates both.

- **“[The] 16-lever schema”** ([spec:41](docs/superpowers/specs/2026-09-24-frontend-learning-redesign-design.md#L41)). The canonical schema contains **17** levers: three taxes, ten ordered levers, and four simple enums ([backend/policy_schema.py:16](backend/policy_schema.py#L16), [backend/policy_schema.py:22](backend/policy_schema.py#L22), [backend/policy_schema.py:35](backend/policy_schema.py#L35), [backend/policy_schema.py:73](backend/policy_schema.py#L73)). **Design impact:** the custom-policy editor and contract tests need an explicit decision about which lever, if any, is omitted.

- **“A week of groceries” means “Average price of one person’s food for a week”** ([spec:25](docs/superpowers/specs/2026-09-24-frontend-learning-redesign-design.md#L25)). The available sector field is a mean **posted food price**, not a weekly per-person basket or actual amount paid after subsidy ([backend/server.py:785](backend/server.py#L785), [backend/economy.py:1360](backend/economy.py#L1360)). **Design impact:** either relabel it as a unit price or define and compute a basket and an out-of-pocket measure.

- **“Firm counts by state”** and **“All firms ranked richest first … Closed”** ([spec:29](docs/superpowers/specs/2026-09-24-frontend-learning-redesign-design.md#L29), [spec:71](docs/superpowers/specs/2026-09-24-frontend-learning-redesign-design.md#L71)). Bankruptcy removes firms from the live `economy.firms` collection; the existing tracked-firm list skips missing IDs ([backend/economy.py:4964](backend/economy.py#L4964), [backend/server.py:2432](backend/server.py#L2432)). **Design impact:** “closed” requires a retained tombstone or event-derived archive, with a defined time window. It cannot be one state in the live full-firm list.

- **“All [section 6 changes] are widenings of the existing frame and protocol, not new machinery”** ([spec:155](docs/superpowers/specs/2026-09-24-frontend-learning-redesign-design.md#L155)). `SETUP` currently knows one session, `TRACK` does not exist, and the loop has no horizon or completion command ([backend/server.py:137](backend/server.py#L137), [backend/server.py:3219](backend/server.py#L3219), [backend/server.py:3262](backend/server.py#L3262)). **Design impact:** an experiment coordinator, tracking lifecycle, and finish semantics are new behavior.

- **“The same seed always builds the same town”** and the **“under a minute”** two-arm estimate ([spec:39](docs/superpowers/specs/2026-09-24-frontend-learning-redesign-design.md#L39), [spec:48](docs/superpowers/specs/2026-09-24-frontend-learning-redesign-design.md#L48)). The checked-in determinism result applies to a fixed seed **and policy**, at 10,000 households over 80 ticks; it does not establish the proposed concurrent-browser latency ([policy_forecasting/RESULTS.md:7](policy_forecasting/RESULTS.md#L7)). Tick compute time is measured before frame construction, JSON sending, and the loop’s sleep ([backend/server.py:2524](backend/server.py#L2524), [backend/server.py:2609](backend/server.py#L2609), [backend/server.py:2661](backend/server.py#L2661)). **Design impact:** qualify the reproducibility copy and benchmark the whole proposed path.

- **“Runner and CSVs: session scratchpad `smoke-sweep/`”** ([spec:115](docs/superpowers/specs/2026-09-24-frontend-learning-redesign-design.md#L115)). Those artifacts are not in the repository; the checked-in `RESULTS.md` documents a different 10,000-household, 80-tick sweep ([policy_forecasting/RESULTS.md:1](policy_forecasting/RESULTS.md#L1)). **Design impact:** the two-card launch choice rests on results a reviewer cannot reproduce or inspect.

## C. Frontend architecture

Multiple sockets are feasible: the server test proves distinct managers for simultaneous connections ([backend/tests_server/test_server_sessions.py:19](backend/tests_server/test_server_sessions.py#L19)). The current client, however, has one `ws` ref, one reconnect timer, one session ID, and one message handler; on reconnect the backend creates a fresh manager while the frontend retains its old displayed state ([frontend-react/src/App.jsx:38](frontend-react/src/App.jsx#L38), [frontend-react/src/App.jsx:182](frontend-react/src/App.jsx#L182), [frontend-react/src/App.jsx:310](frontend-react/src/App.jsx#L310), [backend/server.py:3204](backend/server.py#L3204)). The new store must key every message by arm and session generation, reject late messages from an old socket, and choose whether reconnect restarts the whole experiment or marks an arm lost.

Keeping every **raw** frame is expensive because each frame repeats growing history arrays and tracked-subject histories ([backend/server.py:2374](backend/server.py#L2374), [backend/server.py:2639](backend/server.py#L2639)). The checked-in tick-60 fixture is about 44 KB in compact JSON with only 12 subjects and seven firms; at that *illustrative* size, four arms × 520 frames are already about 91 MB of wire JSON before the proposed expansion and JavaScript object overhead ([frontend-react/src/test/fixtures/frame.json:1](frontend-react/src/test/fixtures/frame.json#L1), [backend/server.py:359](backend/server.py#L359)). Store normalized per-tick facts and bounded events, not repeated whole frames. Measure 1,000- and 5,000-household cases with warehouse on and off, including serialization, browser parsing, retained heap, and chart rerender time.

`alignByTick` correctly unions sparse tick sets and uses `null` for missing values, but `TimeSeries` defaults to the last **250** points and sets its x-domain from available first/last data ([frontend-react/src/charts/TimeSeries.jsx:30](frontend-react/src/charts/TimeSeries.jsx#L30), [frontend-react/src/charts/TimeSeries.jsx:69](frontend-react/src/charts/TimeSeries.jsx#L69), [frontend-react/src/charts/TimeSeries.jsx:179](frontend-react/src/charts/TimeSeries.jsx#L179)). It cannot, unchanged, show a fixed 260–520-tick horizon with empty future and a common cursor. Its marker style also assumes AI versus generic accent rather than one color per arm ([frontend-react/src/charts/TimeSeries.jsx:253](frontend-react/src/charts/TimeSeries.jsx#L253)). Reuse the alignment helper, but specify StoryChart behavior separately.

## D. Experiment model

The spec needs explicit state transitions and failure rules. If one arm disconnects, continuing the others destroys a live matched comparison; reconnect cannot resume the old manager ([backend/server.py:3286](backend/server.py#L3286)). Decide whether to pause all, restart all from seed and recorded actions, or finish with an incomplete verdict. If arms drift, define whether controls pause faster arms, whether the cursor can reach an arm’s live edge, and when a 12-week outcome comparison is allowed ([spec:45](docs/superpowers/specs/2026-09-24-frontend-learning-redesign-design.md#L45)).

A “finished” horizon has no server command today: `STOP` only pauses and flushes, while `RESET` zeroes the manager tick without rebuilding its economy; only `SETUP` makes a fresh world ([backend/server.py:3262](backend/server.py#L3262), [backend/server.py:3266](backend/server.py#L3266), [backend/server.py:1853](backend/server.py#L1853)). Moreover, warehouse `analysis_ready` is set only for a completed close, which the current WebSocket commands never request ([backend/server.py:1803](backend/server.py#L1803)). Define how all arms finish together, how “Extend a year” reopens or postpones finalization, and whether “Reset” repeats the same seed and clears actions, history, and warehouse identity. A second tab can consume another one to four sessions against the default eight-session cap, and has no shared experiment ownership ([backend/server.py:2865](backend/server.py#L2865)).

## E. LLM mode

The pipeline already supplies provider/model, snapshot and applied ticks, requested and applied changes, rejection reason codes, public rationale, evidence audit, elapsed milliseconds, and provider status in the latest decision or durable decision row ([backend/server.py:1404](backend/server.py#L1404), [backend/server.py:1585](backend/server.py#L1585), [backend/server.py:1677](backend/server.py#L1677)). The decision card still needs substantial work. The model’s public rationale is truncated to 500 characters, so “Read all 640 words” cannot be backed by the current result ([backend/tools/llm/llm_government.py:2399](backend/tools/llm/llm_government.py#L2399)). Rejection reasons are machine codes, not quoted friendly rules; the mockup’s **three-point** tax rule is wrong because the schema limit is **five** percentage points ([backend/policy_schema.py:13](backend/policy_schema.py#L13), [docs/superpowers/specs/2026-09-24-mockups/03-run-ai-mayor.html:145](docs/superpowers/specs/2026-09-24-mockups/03-run-ai-mayor.html#L145)).

The current evidence audit checks structured cited `key=value` items, not all factual claims in prose. It can mark a key as matched when no value was cited, and its comparison map mixes raw and observed values ([backend/tools/llm/llm_government.py:790](backend/tools/llm/llm_government.py#L790)). Therefore “3 of 4 claims matched the data” and “reasons matched the data” require a new, defined audit method and denominator; they cannot be derived honestly from current statuses. Provider failure disables the advisor while the ordinary simulation continues, so an AI arm can silently become an unguided run unless the UI stops or clearly reclassifies it ([backend/server.py:1456](backend/server.py#L1456)).

## F. Question cards and smoke-run conclusions

The checked-in 10,000-household sweep supports **simulator-only**, matched-seed effects over an 80-tick window, including lower unemployment for high minimum wage and higher unemployment for high benefits ([policy_forecasting/RESULTS.md:33](policy_forecasting/RESULTS.md#L33), [policy_forecasting/RESULTS.md:39](policy_forecasting/RESULTS.md#L39)). The spec’s uncommitted 1,000-household smoke run reports the opposite benefits direction over five years ([spec:119](docs/superpowers/specs/2026-09-24-frontend-learning-redesign-design.md#L119)). Holding three cards is a reasonable conservative choice, but “Promise lower unemployment and higher pay” in the minimum-wage table conflicts with the later rule that card copy never promises direction ([spec:105](docs/superpowers/specs/2026-09-24-frontend-learning-redesign-design.md#L105), [spec:134](docs/superpowers/specs/2026-09-24-frontend-learning-redesign-design.md#L134)). Two seeds and ten checkpoints show visibility in those runs; they do not establish general reliability at the launch default.

Before changing the economic model, cheaper display experiments are available: use **household out-of-pocket food spending and distress**, rather than posted food price, for the subsidy card because the treasury pays part of the purchase ([backend/economy.py:1190](backend/economy.py#L1190), [policy_forecasting/RESULTS.md:44](policy_forecasting/RESULTS.md#L44)); show authorized jobs and treasury cost over a shorter horizon for public works ([backend/economy.py:6282](backend/economy.py#L6282), [backend/economy.py:6341](backend/economy.py#L6341)); and try fewer starting firms per sector, a shorter horizon, or allowed stronger lever values before discarding tax questions ([backend/server.py:141](backend/server.py#L141), [backend/policy_schema.py:16](backend/policy_schema.py#L16)). Each alternative still needs recorded matched-seed evidence. The reported public-works “100 jobs” also needs labeling as actual hires if that is what was measured: its configured target at 1,000 households is 200 jobs ([backend/config.py:655](backend/config.py#L655), [backend/economy.py:6282](backend/economy.py#L6282)).

## G. Missing pieces

Specify setup failure, session-capacity, partial-run, stale-data, empty-event, no-firm, and provider-unavailable states; today the protocol returns plain error objects and a capacity rejection closes the socket ([backend/server.py:3204](backend/server.py#L3204), [backend/server.py:3234](backend/server.py#L3234)). Define keyboard and screen-reader access to the SVG town, houses, scrubber, chart markers, and drawer; the mockup’s “click a house” interaction has no equivalent path in its static markup ([docs/superpowers/specs/2026-09-24-mockups/02-run-compare-policies.html:147](docs/superpowers/specs/2026-09-24-mockups/02-run-compare-policies.html#L147)). Put friendly names, units, definitions, and narration templates in a localization-ready catalog rather than embedding English sentences in components. Set measurable frame-size, tick-time, browser-heap, and chart-interaction budgets. Record experiment and arm IDs, policy action IDs, frame schema version, connection loss, and completion status so a verdict and Saved comparison can be traced to their inputs. Saved also needs HTTP proxy wiring: production Nginx currently forwards `/ws` and `/health`, but not `/warehouse` ([frontend-react/nginx.conf:8](frontend-react/nginx.conf#L8), [frontend-react/nginx.conf:18](frontend-react/nginx.conf#L18), [frontend-react/nginx.conf:23](frontend-react/nginx.conf#L23)).

## H. Changes to make before an implementation plan

1. Define a server-owned experiment identity, arm registration, reservation and cleanup protocol that enforces the 10,000-household total across sockets.
2. Specify validated initial policy vectors, including grouped levers, and correct the schema count from 16 to 17.
3. Define finish, pause, reset, extend, disconnect, reconnect, second-tab, and incomplete-comparison semantics alongside warehouse completion status.
4. Replace “route warehouse events into the frame” with a typed event inventory, missing producers, stable IDs, aggregation rules, and cost limit.
5. Define a compact frame and browser retention model, then benchmark concurrent arms at 1,000 and 5,000 households with serialization and rendering included.
6. Define each friendly metric’s source, unit, freshness, null behavior, and whether it represents posted price, paid price, cash, or wealth.
7. Specify the AI decision audit and truth-pair schema, correct the five-point tax rule, and remove claims of full rationale or scored reasoning until supported.
8. Check in the smoke-run runner and artifacts, reconcile the contradictory card copy, and test cheaper visibility changes before requiring calibration.
9. Add provider failure, accessibility, localization, telemetry, and Saved HTTP access requirements to the phase acceptance criteria.
