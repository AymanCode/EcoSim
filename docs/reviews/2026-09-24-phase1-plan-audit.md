4. **Task 3, step 3 — FINISH is undone by disconnect.** FINISH retains `warehouse_run_id`; disconnect subsequently calls `_close_warehouse_run("stopped")`, overwriting completed status and clearing analysis readiness ([server.py:3286](/Users/aymanislam/EcoSim_v_2/EcoSim/backend/server.py:3286), [server.py:1813](/Users/aymanislam/EcoSim_v_2/EcoSim/backend/server.py:1813)). Simply calling the current status updater with `"running"` is insufficient: it always sets `ended_at` ([db_manager.py:152](/Users/aymanislam/EcoSim_v_2/EcoSim/backend/data/db_manager.py:152)).

6. **Task 5, steps 3 and 5 — real events disappear or collide.** Manual changes are recorded before `self.tick` increments ([server.py:2118](/Users/aymanislam/EcoSim_v_2/EcoSim/backend/server.py:2118)); payment defaults record zero-based `current_tick` ([payment_loans.py:317](/Users/aymanislam/EcoSim_v_2/EcoSim/backend/payment_loans.py:317)). 8. **Task 8, step 3 — smoke checkpoints are misaligned.** Both benchmark signatures are correct, but smoke row `tick=N−1` describes N completed steps ([run_newcomer_smoke.py:188](/Users/aymanislam/EcoSim_v_2/EcoSim/backend/tools/benchmarks/run_newcomer_smoke.py:188), [run_newcomer_smoke.py:247](/Users/aymanislam/EcoSim_v_2/EcoSim/backend/tools/benchmarks/run_newcomer_smoke.py:247)).
